# DriveSchool

DriveSchool е уеб приложение за управление на шофьорска школа. То е изградено с ASP.NET Core MVC, Razor Views, ASP.NET Core Identity, Entity Framework Core и Microsoft SQL Server. Интерфейсът е на български и не използва отделно JavaScript приложение.

## Стартиране

Нужни са .NET 10 SDK и достъп до Microsoft SQL Server.

1. Добавете SQL Server connection string в Replit Secrets с име `SQLSERVER_CONNECTION_STRING`. Не го записвайте в код или в този файл.
2. В директорията `DriveSchool` изпълнете `dotnet tool restore`, ако `dotnet-ef` инструментът още не е възстановен.
3. При стартиране приложението прилага EF Core миграциите. В среда Development то създава демонстрационните роли и данни.

За локална среда използвайте .NET User Secrets с ключа `ConnectionStrings:DefaultConnection` или задайте `SQLSERVER_CONNECTION_STRING` чрез secret manager. След настройка изпълнете:

```bash
cd DriveSchool
dotnet tool restore
dotnet ef database update
```

Не поставяйте connection string в код, Git, споделен терминал или снимка на екрана. Използвайте Replit Secrets или локален secret manager.

За нова миграция:

```bash
dotnet ef migrations add <MigrationName>
dotnet ef database update
```

След промените за кандидатстване на инструктори създайте миграция с име `InstructorApplications` и приложете базата данни. В Visual Studio Package Manager Console командите са `Add-Migration InstructorApplications` и `Update-Database`.

Използваната команда за генериране на миграции е `dotnet-ef` 10.0; Entity Framework Core и SQL Server provider са от серия 10.0.

## Роли и достъп

- **Собственик** — административно табло, курсисти, инструктори, автопарк, записвания, график, уроци, плащания, статистика, тестове и профили.
- **Инструктор** — назначени курсисти, личен график, заявки за час, проведени уроци, оценки и теоретични тестове.
- **Курсист** — собствен профил, инструктор, заявки за час, график, напредък, тестове и история на плащанията.

Ролите се проверяват от MVC authorization атрибути на сървъра. Публичната регистрация позволява създаване на профил на курсист или кандидатстване за инструктор.

### Кандидатстване за инструктор

При избор на тип профил „Инструктор“ регистрационната форма изисква телефон, професионално представяне, години опит, категории за обучение, данни за обучителния автомобил и CV файл (PDF/DOC/DOCX до 5 MB). CV файловете се съхраняват в `App_Data/InstructorCVs`, извън публичната `wwwroot` директория.

Новата кандидатура се записва със статус „Чака одобрение“. Кандидатът не се вписва автоматично и няма достъп до инструкторското табло, докато администратор не одобри профила от **Админ табло → Инструктори**. Администраторът може да изтегли CV-то и да одобри или откаже кандидатурата.

Парола за всички демонстрационни профили: `DriveSchool.Dev2026!`

Тези профили и пароли са само за Development. Не изпълнявайте demo seeder върху production база и сменете паролите преди споделяне на Development среда.

За първоначален production собственик задайте `DRIVESCHOOL_OWNER_EMAIL` и `DRIVESCHOOL_OWNER_PASSWORD` като променливи за инициализация. След като профилът бъде създаден, премахнете тези стойности. Ролите се създават при инициализацията на базата.

## Основни правила

- Слотите се резервират със server-side availability checks и SQL Server serializable transactions, за да се предотвратяват застъпвания.
- Студентът може да отмени час до 24 часа преди началото; слотът се освобождава.
- Теоретичните тестове се оценяват автоматично. Сървърът проверява времето за изпълнение и записва резултата.
- Инструкторите могат да отварят само профилите на курсистите, които са им назначени; курсистите виждат само собствените си записи.
- Плащанията са регистър на задължения и получени суми. Онлайн картови плащания не са свързани.
- Контактната информация и демонстрационното съдържание трябва да бъдат заменени с реалните данни на школата преди публикуване.

## Ако SQL Server не е конфигуриран

Публичните страници могат да се отварят, но автентикацията и функциите с данни остават недостъпни. Приложението не преминава към SQLite, PostgreSQL или локално съхранение.
